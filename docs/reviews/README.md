# 外部子 Agent 调用与审查处理

本目录是实际本地 Freebuff（用户所称 Freebuf）及 OpenCode 调用的脱敏导出。INVOCATIONS.json 从真实日志提取调用时间、工具事件、原始文件 SHA-256 和报告 SHA-256；原始记录保留在开发电脑。过滤导出不是完整逐字会话。

Freebuff 0.2.36 实际使用 DeepSeek V4.1 Flash Slow / low，独立检查了基线及升级快照，编写了报告、复核和验收检查器。其 shell 工具未能使用 Git Bash，因此不能声称它亲自运行真机测试。检查器由主执行端在真实分析结果上执行，保留 FAIL 和 NOT_TESTED。最后的围栏实现复核请求未产出报告，不计为已完成；最终代码另由 OpenCode 静态复核。

OpenCode 1.19.5 实际参与历史续传、性能审查、存储失败围栏、观察脚本、文档、打包工具及最终独立源码复核。各报告中的“实际执行”限定于该子任务；编译、合成夹具和真机验收分别记录。

## Freebuff 意见处理

- “RFCOMM 丢中间帧仍可继续提交并静默丢历史”的机制不成立：可靠有序流与严格加密计数器会使连接失败。Freebuff 已在 RECHECK 撤回。UI 合并不跳过历史入库任务。
- 真正问题是 SQLite 批次失败被吞掉，后续批次可能越过未提交事件推进检查点。已改为本地可信连接代次、单写入队列拒绝旧代次、只关闭所属连接，下次从已提交检查点重放；检查点和事件同一事务。7 项 JVM 合成围栏检查通过；未做真机磁盘满/损坏故障注入。代次由认证后的本地连接生成，覆盖来自网络的字段；Wi-Fi 剥离该字段，无需将本地所有权字段当作远端协议输入。
- 1800 秒不超过 3600 秒上限；physicalNetworkHz 表示物理呈现的新状态；无 flush 提示不等于丢 marker；多数 jank 是 Buffer Stuffing，不能全部算 deadline miss。这些误读在 RECHECK 已纠正。
- 最终发送账本先注册、后写入，以避免早到 ACK 竞争；进程终生成功发送统计只在加密 STATE 写成功后递增，不包括控制帧。旧报告对该顺序的描述只适用于旧快照。
- 续传游标使用最后提交事件 ID；超时、未知或已裁剪游标安全回退重放，旧 v1 仍可用。保留边界之外的历史不承诺恢复。忙数据库回退可能增加重放量；历史事件不是遥测队列，不以 UI 丢旧值策略丢弃。

## 验收范围

最终短窗口与早期 30 分钟候选具有不同二进制哈希，禁止混为同一轮。最终短窗口网络数据年龄达预算，但 CPU/RAM 首次显示年龄 P95、严格 10Hz 和稳定 60FPS 尚未全部达到。24 小时测试由用户取消，Windows 操作系统重启/睡眠未测。详细数值见 ../031-MEASUREMENT.md。

## 最后收尾说明

部分原始报告中的“手机最终记录未取回”“24 小时待测”“审查目录尚未创建”描述的是各调用时点。随后 USB 已接回、已完成的记录已取回，24 小时由用户取消；原报告保留，当前结果以测量文档为准。打包子任务已产出脚本和静态检查记录；主执行端在其等待最终回应时停止 CLI，归档和脱敏扫描由主执行端完成，不归功于该子 Agent。
